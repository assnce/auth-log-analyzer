# Решения и вопросы для ревью

## Почему скользящее окно

Корзины времени могут разделить пять ошибок на две группы, если они попали по разные стороны границы минуты. Здесь каждая новая запись проверяется относительно своего timestamp. Событие ровно на левой границе учитывается.

## Почему IP недостаточно

Один IP может соответствовать VPN-шлюзу или NAT. `possible_password_spray` показывает паттерн, но не устанавливает злой умысел. Дополнительные признаки: MFA, география, user agent, известный сканер, реальные владельцы учётных записей. В этом проекте их нет.

## Почему нет автоматической блокировки

Здесь только offline-триаж. Блокировка без проверки контекста может отключить легитимных пользователей. Инструмент не выполняет сетевых запросов и не изменяет учётные записи.

## Алгоритм и память

Сортировка: O(n log n). Удаление устаревших событий из deque — амортизированное. Для spray на каждом событии пересчитывается множество пользователей, поэтому худшая оценка по времени — O(n²) при большом числе событий в одном окне. Память зависит от входного файла, очередей и сохранённых доказательств; все ключи живут до конца запуска. Для больших потоков нужны счётчики пользователей, очистка неактивных ключей, ограничение evidence и streaming-state.
