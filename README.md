# auth-log-analyzer

**Offline authentication-log triage in Python.** Учебный инструмент SOC: три сценария обнаружения, проверяемые ссылки на события и отчёты JSON/Markdown. Python 3.11+, без внешних зависимостей.

## Быстрый запуск

```bash
git clone https://github.com/assnce/auth-log-analyzer.git
cd auth-log-analyzer
python authlog.py auth.csv
python authlog.py auth.csv --format markdown --output report.md
python -m unittest -v
```

На демонстрационных данных: **13 событий, 3 алерта**. Все учётные записи, адреса и события синтетические; это не данные работодателя.

## Что обнаруживается

| Правило | Условие по умолчанию | Группировка |
|---|---|---|
| `failure_burst` | ≥5 ошибок за 300 секунд | IP + пользователь + хост |
| `possible_password_spray` | Ошибки для ≥5 разных пользователей за 300 секунд | IP + хост |
| `success_after_failures` | Успех после ≥5 ошибок за 600 секунд | IP + пользователь + хост |

Окно скользящее, обе границы включены. Для первых двух правил алерт появляется при пересечении порога снизу, а не на каждом новом событии. После затишья правило может сработать снова. Успешный вход сбрасывает последовательность ошибок этой комбинации IP/пользователь/хост; агрегат spray сохраняется. Неудачные события на разных хостах не объединяются.

```bash
python authlog.py auth.csv --failure-threshold 7 --failure-window 600 --spray-users 8
python authlog.py auth.csv --fail-on-alert
```

Коды возврата: `0` — обработка выполнена, `1` — есть алерты и задан `--fail-on-alert`, `2` — ошибка входных данных или записи отчёта.

## Контракт данных

CSV с заголовком или JSONL с одним объектом на строку:

```json
{"event_id":"e001","timestamp":"2026-10-01T10:00:00Z","source_ip":"192.0.2.10","username":"alice","host":"vpn-01","outcome":"failure"}
```

Все шесть полей обязательны и являются непустыми строками. `outcome` — только `success` или `failure`. Время — ISO 8601 с часовым поясом, внутри приводится к UTC. IPv4/IPv6 проверяются и нормализуются. `event_id` уникален во всём файле. Дополнительные поля игнорируются. Невалидная запись останавливает обработку с номером строки; тихого пропуска нет.

Это **нормализованный формат**, не универсальный парсер EVTX/syslog. Для реальных источников сначала нужен отдельный адаптер. Имена пользователей/хостов сравниваются точно, включая регистр; нормализация доменов и имён — ответственность адаптера.

## Как читать результат

Алерт содержит идентификаторы всех событий, начало окна, IP, хост и пользователей. `report.json` и `report.md` получены запуском CLI. Уровни medium/high обозначают приоритет первичной проверки, а не подтверждённую компрометацию.

1. Проверить источник и полноту журналов.
2. Сопоставить IP с VPN, NAT, сканерами и инфраструктурой организации.
3. Уточнить MFA, результат входа и активность после него.
4. Записать факты и пробелы, затем принять решение об эскалации.

## Проверка и ограничения

Тесты покрывают границы временных окон, разные IP/хосты, уникальность пользователей, повторные алерты, сброс после успеха, часовые пояса, IPv6, повреждённые записи и дубликаты ID.

События загружаются в память и сортируются по времени. При одинаковых timestamps сохраняется порядок входного файла. Это пакетный учебный анализатор, без streaming, enrichment, хранения состояния между запусками и измеренного production-SLA. NAT, ошибки пользователей и автоматизация могут давать ложные срабатывания. Распределённые и медленные атаки могут не достигать порогов. Отсутствие алерта не доказывает безопасность.
